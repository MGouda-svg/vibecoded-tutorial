§1 · What is vibe coding

A definition

There's a new kind of coding I call “vibe coding”, where you fully give in to the vibes, embrace exponentials, and forget that the code even exists.
— Andrej Karpathy, February 2025

By the end of 2025 it was Collins Dictionary's Word of the Year. Today it broadly means building software mostly through conversation with an AI.

01 · DESCRIBESay what you want

In plain language: the goal, the data, the constraints.

02 · GENERATEAI writes & runs it

Code, files, commands, often in one go.

03 · STEERJudge the result

Look at the output, not the syntax. Give feedback. Repeat.

Vibe Coding for Researchers
Karpathy's original tweet was half-joking, about weekend projects. The term stuck. Emphasise the loop: describe, generate, steer. Steering is where your expertise as a researcher matters.
§1 · What is vibe coding

From typing code to directing it

Each generation of tools takes on a bigger piece of the work.

~2021Autocomplete

Finishes the line you're typing.

e.g. early GitHub Copilot

~2023Chat assistant

Answers questions; you copy-paste snippets back and forth.

e.g. ChatGPT, Claude.ai

~2024AI-native editor

Edits across many files in your project.

e.g. Cursor, Copilot edits

2025 →Autonomous agent

Plans, writes, runs, tests and fixes, then reports back.

e.g. Claude Code, Codex

Your role moves from typist → reviewer → director.

The spectrum runs from pure vibes (accept everything) to AI-assisted engineering (review everything). For research, aim for the second.

Vibe Coding for Researchers
Dates are approximate. The point: the unit of delegation keeps growing, from a line, to a snippet, to files, to a whole task.

§1 · What is vibe coding

Honest caveats

It's powerful, and it can be confidently wrong.

01Plausible ≠ correct

Invented functions, wrong units, silently dropped rows. Code that runs can still produce the wrong science.

02Security & privacy

Leaked API keys, unsafe dependencies, unpublished data sent to a cloud model. Know your institution's policy.

03Faster isn't guaranteed

A 2025 METR study: experienced developers were 19% slower with AI tools on their own repos, while believing they were ~20% faster.

04You own the output

Your name is on the paper. If you can't explain and defend the code, you can't trust the result.

Vibe Coding for Researchers
METR, July 2025, randomized controlled trial with 16 experienced open-source developers on mature codebases. That doesn't mean AI is useless; it means measure, don't assume. Gains are biggest on unfamiliar tasks and boilerplate.

§2 · Why researchers should care

Before / after: drafting a SLURM job script

BEFOREAn afternoon of docs

Search “SLURM job array”, copy a colleague's script, guess the flags, fail, read logs, retry.

After: one prompt, on your laptop
> Write a SLURM array job that runs simulate.py for 100 temperatures between 1 and 5 K. 4 GB and 2 h per task, one log per task, results in results/.

Then ask: “what could go wrong?” (one real bug is hiding in there)

sweep.sbatch · drafted locally · human-reviewed before sbatch#!/bin/bash #SBATCH --job-name=temp_sweep #SBATCH --array=0-99 #SBATCH --time=02:00:00 #SBATCH --mem=4G #SBATCH --output=logs/%x_%A_%a.out # map task id 0..99 → temperature 1..5 K T=$(python -c "import numpy as np; \ print(np.linspace(1, 5, 100)[$SLURM_ARRAY_TASK_ID])") mkdir -p results logs python simulate.py --temperature "$T" \ --out "results/run_${SLURM_ARRAY_TASK_ID}.h5"
Vibe Coding for Researchers
Framing: the AI drafts the script locally; no agent runs on the cluster. You read, understand and submit it yourself. Always review generated job scripts: wrong memory or time limits waste allocation. Note the agent picked sensible defaults (log naming %x_%A_%a) a beginner wouldn't know. The hidden bug (deliberate): SLURM opens logs/... before the script runs, so the "mkdir -p logs" inside the script comes too late. The first run fails unless logs/ already exists. Ask the audience to spot it; then show that asking the agent "what could go wrong?" catches it. Verification in action.

§2 · Why researchers should care

Good research hygiene with AI

Five habits that make vibe-coded research trustworthy.

01Use git

Commit before every AI change. It's your undo button and your audit trail.

02Verify

Check against analytic results, small cases and unit tests, not vibes.

03Protect data

No sensitive, unpublished or human-subject data in cloud tools without approval.

04Pin environments

requirements.txt / environment.yml. Record the tool and model you used.

05Disclose

Follow journal and funder AI policies. Mention AI assistance in methods.

Rule of thumb

If it ends up in a paper, a human has read every line of it.

LLM & the context window

LLM: the engine

A Large Language Model predicts the next piece of text (a token, roughly ¾ of a word). Trained on huge amounts of text and code. Claude, GPT and Gemini are LLMs.

Context window: its working memory

Everything the model can see right now: instructions, your messages, files it read, tool output. Today that's roughly 200K–1M tokens. Anything outside it doesn't exist for the model.

Prompt engineering

Writing instructions the way you'd brief a smart new colleague who knows nothing about your project.

Weak
> make me a website
The ingredients
contextgoalinputsconstraintsdone-whenexamples

The first answer is a draft. Iterate.

Strong
> [context] I'm a physics PhD student. Build me a one-page academic portfolio. [inputs] cv.pdf, my GitHub and Google Scholar profiles. [goal] Sections: bio, research, publications, projects, contact. [constraints] Plain HTML/CSS, no frameworks, mobile-friendly, accessible, deployable to GitHub Pages. [done-when] No console errors, and you've checked it in a browser at phone and desktop widths.

§3 · Vocabulary · 4 / 8

Plan mode: measure twice, cut once

The agent may explore and ask questions, but it can't change anything until you approve a plan.

01Explore & ask

Reads your files, asks clarifying questions.

02Propose a plan

Steps, files to touch, how it will verify.

03You review → approve

Edit it, push back, or start over. Cheap now, expensive later.

§3 · Vocabulary · 5 / 8

CLAUDE.md / AGENTS.md: the project's memory

A plain Markdown file in your project, read automatically at the start of every session.

Same idea, two names

AGENTS.md: open, cross-tool standard (Codex, Cursor, Copilot, Gemini CLI…).
CLAUDE.md: Claude Code's version.

What goes in it

  • What the project is & who it's for
  • How to build / run / test
  • Conventions and hard rules

Short and specific beats long and vague: it costs context every session.

This project's CLAUDE.md
# project context You are an expert in vibe coding, giving an introductory tutorial for researchers along with a live vibe-coding demo. # instructions 1. keep CLAUDE.md updated 2. don't make assumptions, ask questions 3. use available skills and tools

Skills: expertise on demand

A folder of instructions, scripts and references the agent loads only when the task needs it.

How it stays cheap

Only each skill's name + one-line description sits in context. The full instructions load when relevant. This is called progressive disclosure.

§3 · Vocabulary · 7 / 8

MCP: “USB-C for AI tools”

The Model Context Protocol: one open standard for connecting agents to outside apps and data.

Why it matters

Write a connector once and it works in many AI apps. Introduced by Anthropic (Nov 2024), now supported by most major tools.

What it adds

Tools the agent can call: open a web page, read a Drive file, create a GitHub repo, query a database.

Careful: an MCP server acts with your permissions. Install only ones you trust.

Vibe Coding for Researchers▶ IN THE DEMO · browser reads Scholar & GitHub; GitHub deploys
Analogy: before USB, every device had its own cable. MCP is the common plug. Spec and server list at modelcontextprotocol.io.
§3 · Vocabulary · 8 / 8

Subagents: a team, not a soloist

The main agent hands off focused jobs to helpers. Each has a fresh context and returns only a summary.

Why

  • Parallel: independent jobs run at once
  • Clean context: the main agent sees results, not the mess
  • Specialised: each can have its own instructions

Trade-off: more tokens, so more cost. Use them for big, independent, parallel work.
